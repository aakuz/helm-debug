# Domain docs

## Before exploring

Read `GLOSSARY.md` at the repository root and the ADRs under
`docs/adr/` relevant to the area being explored.

If a document is absent, proceed silently. The domain-modeling
skill creates documents when terms or decisions are resolved.

## Layout

This repository uses a single-context layout:

- `GLOSSARY.md`: shared domain vocabulary.
- `docs/adr/`: architectural decisions.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses,
and test names. If a concept is missing, reconsider the term
or note the gap for domain-modeling.

## ADR conflicts

Explicitly identify proposals that contradict an existing ADR,
cite that ADR, and explain why the decision should be reconsidered.
